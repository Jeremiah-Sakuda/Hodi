## 1. Features and functionality

**Your voice is in a product you never agreed to.** There was no mechanism by which you could have agreed, refused, priced, or revoked. *Hodi* is what you call at someone's door before entering. **Hodi is the knock.**

Hodi is a governed fleet of institutional agents that administers creative consent end to end.

**Register a work with proof of control.** Five registered works drawn from the author's own output — Medium essays, public repositories, bass recordings — rather than a synthetic corpus. Stated precisely, because the manifest is one `curl` away: **no work currently sits at `verified_control`** — all five are `asserted`, and two of those are demonstration registrations whose canonical URIs do not currently resolve. The repository work claimed `verified_control` on a signed-commit proof until 2026-08-25, when an audit found the repository has never had a signed commit and the function that issued the proof verified nothing; it now refuses unless git reports a good signature. That is the tiering working as designed — `asserted` is never hidden and never upgraded — but "five real works" would overstate what a reader can verify today. Every registration carries a mandatory `control_tier`: `verified_control` (with a stored, resolving proof), `asserted`, or `disputed`. The schema makes `verified_control` without a stored proof unconstructible, and `make verify-manifest` re-fetches the live manifest and fails if any proof URI stops resolving. A live audit caught three works claiming `verified_control` on fictitious proofs; they were downgraded to `asserted` and the daily check exists so that cannot recur.

**Express scoped, machine-readable terms.** A `Scope` is five dimensions — use type, model class, commercial status, territory, temporal validity. Use types form a declared partial order (`training ⊃ fine_tuning ⊃ rag_retrieval ⊃ human_reference`; `synthesis` incomparable), stated as **data**, never as branching logic. `permits()` resolves containment across all five dimensions simultaneously, per grant, never merging dimensions across grants — so a `fine_tuning` grant plus a separate `commercial` grant can never compose into commercial fine-tuning. A 56-case truth table runs in CI via `make verify-scopes`.

**Ask in plain English.** `POST /api/v1/license/natural` takes a natural-language request — *"we'd like to fine-tune an open-weights model on this work for non-commercial research, US and Canada only"* — and Gemini 3.5 Flash structures it into a typed `Scope`. **The model interprets intent. The lattice decides permission.** Gemini's only power is to produce a schema-validated `Scope`; a malformed, out-of-vocabulary, or extra-field interpretation is rejected with HTTP 422, never coerced. A test injects an interpretation smuggling `{"permitted": true}` and asserts it is *rejected*, not stripped. Gemini never grants anything.

**Evaluate each buyer's request under confidentiality, enforced structurally.** Four agents separated by **conflict of interest, not task**: the rights custodian holds artist identity; the licensing negotiator sees one counterparty per session and must be *incapable* of reading another's terms; the evidence agent must not see commercial terms or its findings become interested; the revocation propagator must not hold identity. No service account holds two of {identity, buyer terms, evidence, revocation}. A monolith here would itself be the violation. Every inter-agent call passes a gateway that logs each denial as a structured `PolicyDenialEvent` — never a silent refusal, and never a stack trace.

**Revoke, and terminate exactly the grants that permitted the use.** Revoking use type R terminates every active grant that *permits* R — the same `permits()` predicate the licensing path uses, so a grant falls exactly when it could have exercised the revoked use. The withdrawal's `derived_scopes` (R and everything R contains) are walked from the lattice, not enumerated in code; affected grants get notices with receipts. In the last verified deployment those artifacts carry Cloud KMS ECDSA P-256 signatures verifiable from the published public key; historical unsigned and revoked-signature vintages remain visible because the log is append-only. The original grant stays visible and struck through. Revocation is a **new event that supersedes**; nothing is ever mutated or deleted. **Corrected, and disclosed:** through 2026-08-10 the selection was inverted — it terminated the revoked type's *descendants*, destroying narrower licenses the artist never revoked, and an earlier test had blessed that as correct. All 25 (held × revoked) cells are now asserted against `permits()` as an independent oracle (`tests/test_revocation_reach.py`). One scope-model limit remains: terminating a grant held *above* R removes it wholesale, because a single-valued `use_type` on a chain cannot express "training but not fine_tuning" — the safe direction, and only ever for grants that genuinely permitted the revoked use. The full history is in `docs/FINDINGS.md`. Revocation additionally requires that the authenticated artist **owns the work** — checked by a rights-custodian read of `works` before any append.

**Recover from a looping worker.** Force the revocation propagator into an infinite loop and the Supervisor abandons it at its deadline — writing `TaskAbandoned` itself, because the worker is still looping and has reported nothing — the Registry deregisters it for the remainder of the run, and the task reroutes to a standby returning a **stated** partial result: the affected set computed deterministically, with no notices issued and no events appended, because the quarantined worker's write state is unknown and the log is append-only. Quarantine and reroute are both spans in the same trace. Measured on the deployed path: 1113.55 ms server-side average against a 1.0 s deadline.

**Play both sides of the market, live and unauthenticated — safely.** The public site's Studio and Market run every action through the same gateway the fleet crosses, as a `sandbox_agent` role whose policy names every real collection under `denied_collections` — so a demo call aimed at real data is refused by the gateway itself, not by a string check in a route handler (`tests/test_demo_sandbox_boundary.py`, `tests/test_demo_platform_sandbox.py`). Registration stores a **claim** — title, medium, size, browser-computed SHA-256 — never content, because a public unauthenticated upload store is an abuse surface and a rights registry holds claims about works, not masters. The Market's free-text ask is the one public path that spends model quota on anonymous input, so it is bounded three ways (text length, per-session cap, per-IP rate limit). And a revocation **closes the standing offer**, derived from the append-only log: after "I take it back", the very request that was granted a minute earlier is refused, with the reason stated.

**Prove it without credentials.** `make demo` runs the whole spine offline — verified from a clean clone in a fresh container with the network disconnected — and every beat asserts the property it demonstrates rather than printing it.

## 2. Technologies used

- **Gemini 3.5 Flash via Vertex AI** (`gemini-3.5-flash`, `global` endpoint, temperature 0, pinned literal) — natural-language scope interpretation, and revocation-notice drafting gated by a deterministic lint. Availability was probed empirically across nine model IDs and three regions: `gemini-3.5-pro` does not exist in this project's publisher catalog and 404s everywhere; the pro-class 3.x IDs are all previews, which roll, and judging runs past this build. `gemini-3.5-flash` is the newest stable non-preview **3.5-generation** ID reachable, and it is what runs. (`gemini-3.6-flash` also returned 200; it was not adopted — the requirement names 3.5+, the pinned ID was chosen and its latencies measured before 3.6 was probed, and re-pinning a generation days before submission re-opens every recorded timing for no gain.)
- **ADK — Google Agent Development Kit** (`google-adk==2.6.2`) — the runtime agent framework, and it **executes**: the fleet are real `google.adk.agents.BaseAgent` subclasses driven by a real `google.adk.runners.Runner`. They extend `BaseAgent` rather than `LlmAgent` deliberately, because every hop is a deterministic authority decision and a model in that path would contradict the thesis.
- **Gemma, serverless on Vertex AI** (`gemma-4-26b-a4b-it-maas`) — first-pass triage of crawler access records before anything reaches Gemini. Deliberately non-load-bearing: if it is unreachable, Ollama and then a heuristic classify, and evidence records are still produced.
- **OpenTelemetry** — every agent decision emits a span carrying `agent.identity`, `policy.consulted`, and `outcome`, nested inside ADK's own `invoke_agent` spans. A five-hop delegation across three service accounts reads as one trace.
- **Firestore** — the append-only grant-event log. Deterministic event IDs; a custom IAM role (`hodiAppendOnlyGrantWriter`) grants `create`/`get`/`list` and withholds `update` and `delete`. This binds the four agent service accounts **and** the identity the deployed Cloud Run service actually runs as (`hodi-runtime-sa`), so history cannot be rewritten — enforced by IAM at runtime, not only by the code path. Gateway writes use `.create()` (a true append that raises on a duplicate id), never `.set()` (an upsert that both overwrites and requires the `update` permission the runtime identity is denied).
- **Cloud Run** — the deployed evidence endpoint and buyer API, plus the nightly teardown job. `min-instances=0`, `max-instances=5`.
- **Cloud Scheduler** — two jobs with real execution history: a daily accrual audit (09:00 UTC, authenticated by OIDC) and the nightly teardown (23:00 UTC), which has fired on its own cron.
- **Cloud Logging** — gateway denials land as structured `jsonPayload` events, queryable by calling SA, collection, and policy.

**One scope note, stated rather than implied.** The 2026-08-14 live verification established two guarantees. *Append-only* is runtime IAM: the front door executes as a create-only SA (no `update`/`delete`), read back from the deployed revision by a test. *The domain boundary is a credential boundary*: identity, commercial, evidence, and adjudication collections were migrated to their named Firestore databases, each behind a private Cloud Run workload under an IAM-conditioned agent SA; the front door is refused by Google IAM on all four. The shared grant log deliberately remains in `(default)`, where counterparty row separation is gateway-enforced. A post-review change now narrows the revocation worker to `(default)` and makes `/api/v1/revoke` call it without a local fail-open fallback; that cutover is implemented and offline-tested but is not described as deployed until the next live verification records it.

**Published writing:** the defect ledger is written up as **[Seven ways to lie to yourself in code](https://jeremiah-sakuda.github.io/Hodi/blog/seven-ways-to-lie-to-yourself-in-code.html)**, and the project site is at **[https://jeremiah-sakuda.github.io/Hodi/](https://jeremiah-sakuda.github.io/Hodi/)**. **The platform is live at [the service root](https://hodi-evidence-endpoint-406699565497.us-central1.run.app/)** — the Studio, the Market, and the [guided walkthrough](https://hodi-evidence-endpoint-406699565497.us-central1.run.app/demo), all against the deployed service with nothing simulated: a real revocation cascade returns a Cloud KMS signature the page verifies in your own browser, the real ADK fleet delegation runs on click with its Cloud Trace id, and six anonymous attacks are refused live. Social posts carry `#AllThingsAgenticHackathon`.

**Build evidence is in the repository, corrections included:** [`docs/BUILD-LOG.md`](https://github.com/Jeremiah-Sakuda/Hodi/blob/main/docs/BUILD-LOG.md) (every session's verbatim prompt, outcome, and forked decisions, with five dated correction notes), [`docs/FINDINGS.md`](https://github.com/Jeremiah-Sakuda/Hodi/blob/main/docs/FINDINGS.md), [`docs/antigravity/decision.md`](https://github.com/Jeremiah-Sakuda/Hodi/blob/main/docs/antigravity/decision.md), and the write-up [`docs/blog/seven-ways-to-lie-to-yourself-in-code.md`](https://github.com/Jeremiah-Sakuda/Hodi/blob/main/docs/blog/seven-ways-to-lie-to-yourself-in-code.md).

**On the Antigravity SDK.** A pre-committed boolean assertion was tested: *from a headless Cloud Run Job, with no interactive session, the SDK executes a two-agent delegation under distinct service accounts and emits an OpenTelemetry span per agent decision carrying the invoking agent's identity, the policy consulted, and the outcome.* Observed result: the headless job failed at the first check — `No module named 'google.antigravity'`. Antigravity does not currently expose a headless server-side Python surface for multi-agent delegation under distinct service accounts. Partial emission was pre-committed as a fail, so the branch to ADK executed the same day. Published as a negative result with the exact harness and error text, because it is information a reader cannot get elsewhere.

## 3. Other data sources

**The corpus is the author's own published work.** Five real registered works — Medium essays, public GitHub repositories, and original electric bass recordings and stems. No synthetic corpus, and none was ever acquired. This is the only uncontrolled input in the project and it is deliberately real: a rights registry demonstrated on invented works demonstrates nothing about rights.

**Crawler access records are first-party observation.** A Cloud Run evidence endpoint has logged every access since 2026-08-06 — timestamp, path, user agent, source address, referrer, and whether `robots.txt` was fetched first — alongside `/.well-known/hodi.json` declaring machine-readable consent terms and a `robots.txt` referencing them. These are our own logs, not a purchased or scraped dataset.

As of the **2026-08-29** audit: **6956 accrued records**, of which **29 match a crawler user-agent signature**. 6675 are this project's own instrumented tooling. The remaining 281 are non-self-originated but browser-like, and are reported as *unattributed* rather than promoted to crawler access. Those 29 records are the finding: **three distinct crawler-signature user agents, 29 visits between 2026-08-11 and 2026-08-29, twenty-one of them fetching `/robots.txt` — and exactly one, ever, fetching `/.well-known/hodi.json`**, one request away and named in that same `robots.txt`, where the machine-readable terms are served. The consent-fetch count was zero for eighteen days; the claim aged, and the dated audit is what let it age honestly. The vendors are not named here: they did nothing wrong, and the point is not who they are. The figure was 0 until 2026-08-12 and it was wrong — the detector required a word boundary before `bot`, so a vendor prefix glued onto `bot` never matched. `known_crawler_ua_matches` is the only figure this project will describe as crawler access. Regenerate with `make metrics`; `make check-docs` fails the build if this paragraph drifts from `docs/metrics.json`.

**Access records are attributable, not authenticated.** A record captures the user agent a client chose to send and the peer address Cloud Run's front end reports. User agents are self-declared; the client-supplied portion of `X-Forwarded-For` is ignored in favour of the hop the front end appends, which narrows source-address forgery without eliminating it. These records evidence *that a request was made*, never *who made it*.

**Canary strings** were planted in newly published items on 2026-08-06T12:40:00Z. They can only ever protect work published *after* that date; no retroactive coverage is claimed.

**No third-party dataset and no purchased data. No real company is named as a violator anywhere** — every adversary in every fixture is fictional and unnamed (`acme-intelligence-labs`, `rival-labs`, `buyer-acme-*`). One precision: real crawler user-agent *strings* appear in test inputs and in the recorded model-response cache, as classification inputs to the triage engine. They are not accusations and no real party is described as having taken anything. The detector itself no longer enumerates vendor names — it matches generic self-identification (`bot`, `crawler`, `spider`, `scraper`), asserted by a test.

## 4. Findings and learnings

I built a system whose entire premise is refusing to assert what it cannot verify, then kept a ledger of every place it lied to me anyway. **Sixty-six defects, nine classes, and four classes that recurred after being fixed once.** The ledger is the most externally useful thing this project produced.

**Three findings carry the ledger; the full record is one click away.**

**1 · The confidentiality boundary was breakable, and it was broken.** `POST /api/v1/license` took `counterparty_id` from the request body and used it as **both** the query filter **and** the session context the gateway validated that filter against — so one unauthenticated `curl` with `signature: "NOT-A-REAL-SIGNATURE"` returned another counterparty's grant and a receipt in their name. One day later the same class recurred three lines below the fixed handler: `/api/v1/revoke` took no authenticator at all, and under an append-only log those writes were not undoable. The lasting fix is structural on both counts: identity now derives from a verified HMAC credential, the original exploit is a permanent regression test replayed against the deployed service, and a CI guard enumerates the router's own routes and fails if any mutating method reaches an endpoint that never authenticates.

**2 · My own infrastructure became my "third-party crawlers."** The self-traffic list omitted `Google-Cloud-Scheduler`, so the project's own scheduled job was counted as third-party traffic — a false positive that would have inverted the signature finding. After the fix (and a separate detector correction), the audited figure stands at 29 self-identifying crawler visits, of which exactly one has followed the machine-readable consent link. Both false positives and false negatives can turn an empirical claim into a story the data does not support; the number is regenerated from source and the build fails if this text drifts from it.

**3 · The honesty claim itself was overstated, so it was measured.** The README said the overclaim lint catches paraphrases; a 12-paraphrase probe set showed the regex list rejects **4**, and that number was published in place of the claim. An embedding backstop (`gemini-embedding-001`) now takes measured coverage to **12 of 12** — admissible only because it can exclusively ADD a refusal, and both figures stay published because the second depends on a model and falls back to 4 if that model is unreachable. The schema, not the lint, remains the invariant.

The remaining sixty-three entries — including four whole classes of tests that could not fail, and the sharp limit of generation-from-source (it protects against documentation drifting from source, not against the source being read wrongly) — are enumerated in [the defect ledger](https://github.com/Jeremiah-Sakuda/Hodi/blob/main/docs/defect_ledger.json) and written up in [Seven ways to lie to yourself in code](https://jeremiah-sakuda.github.io/Hodi/blog/seven-ways-to-lie-to-yourself-in-code.html).

**What Hodi will not claim, stated as designed limits rather than omissions.** *Training-set membership is not determinable* — membership inference against frontier models is unsolved, the `EvidenceRecord.class` enum has no such value so the schema cannot express it as data, and every record carries a literal `claim_limit` string. *Revocation terminates a grant; it does not un-train a model* — a lint asserts no generated notice implies otherwise. *A crawler user-agent is attributable, not authenticated* — the current audit contains 29 generic crawler-signature matches, but those prove only that requests carrying those self-declared user agents were made. *`verbatim_match` is checked but not demonstrated against a third party.* *The managed Model Armor guardrail was unavailable* — the API is in restricted preview and template creation returned HTTP 403, so the claim was pulled rather than shipped under a Google product's name; prompt inspection is a local regex, labelled `local_regex_inspector` everywhere it appears, and the security posture rests on IAM boundaries, gateway enforcement, and audit traces.

**Google-toolchain findings.** ADK supports fully deterministic multi-agent execution with no LLM in the loop — subclass `BaseAgent`, implement `_run_async_impl` — which matters for any governed system where hops are authority decisions rather than generations; every ADK example we found assumes `LlmAgent`. ADK's own spans compose with application spans, so a delegation across three service accounts reads as one trace carrying both framework and policy attributes. And a sharp edge worth publishing: **`BaseAgent` is a Pydantic model, so shared mutable state passed as a field is deep-copied per agent** — every agent mutated a private copy, the orchestrator saw none of it, nothing errored, and the run "succeeded" while returning empty results.
